# Electronic Patient Record — Living Specification

> **Source of truth for the cross-subproject contract.** This document is the
> canonical artefact for the **electronic patient record entity as a whole**:
> how the trio composes (front-end → service REST/FHIR API → embedded patient
> matcher), the DTO contract (the API identity DTO **is** the matcher's
> `Patient` type, persisted as JSONB), the partition between the thin matchable
> `Patient` identity record and the high-volume clinical record (encounters,
> observations, conditions, medications, allergies, orders, results, notes,
> documents), the append-only versioned clinical record, and the shared
> invariants (audit every read and write, consent before disclosure, no hard
> delete of clinical data).
>
> Each subproject's own `spec/` is the single source of truth **for that
> subproject's internals**. When this spec and a crate spec disagree about
> crate internals, the crate spec wins; when they disagree about the
> integration contract, this spec wins. Open a task in the repo-root
> [`tasks.md`](../tasks.md) to bring the loser in line; do not silently rewrite
> either spec.
>
> **Three-part changes.** A behavioural change is one commit: spec edit + code
> edit + test edit. See
> [`agents/spec-driven-development.md`](../agents/spec-driven-development.md).
>
> **Status (2026-10-20): spec only. No code exists yet.** Every requirement
> below is a target. [`14-implementation-status.md`](14-implementation-status.md)
> records what is built and tested; until it says otherwise, nothing is.

## Shared invariants (summary; §5.8 is canonical)

1. **The clinical record is append-only.** Every change creates a new version
   with author, time, reason and provenance; "delete" is entered-in-error,
   never a row removal. Amendments keep the original visible to authorised
   readers.
2. **Every access is audited**, reads included, with who, what patient, what
   resource, why (purpose of use) and whether break-the-glass was used.
3. **No disclosure without a lawful basis.** Consent and access policy are
   evaluated on every read, in the service, never only in the UI.
4. **Coded where it matters.** Problems, allergies, medications, results and
   vitals carry a code from a named terminology version; free text is kept
   alongside, never instead of, the original.
5. **Absent is not zero.** Missing evidence is `null` with a reason (FHIR
   `dataAbsentReason`), never a default value.
6. **Times are stored in UTC** with the recording zone kept; the user's zone is
   applied at the edge.
7. **People and organisations stay references** (`Practitioner`,
   `PractitionerRole`, `Organization`), never copied strings.
8. **Safety-relevant behaviour is in the hazard log** before it ships.
