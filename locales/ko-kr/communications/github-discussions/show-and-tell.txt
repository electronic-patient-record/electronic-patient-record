만든 것을 공유하세요: 매처가 연결하지 않을 기록을 설명합니다

이 카테고리는 Electronic Patient Record와 함께, 또는 그 주변에서 만든 것을 위한 곳입니다. 연동, 스크립트, 데모, 튜토리얼, 실험 등입니다. 형식을 보여 주기 위해, 프로젝트가 이미 하는 작은 일을 소개합니다.

## 무엇인가

매처(matcher)는 두 환자 신원 기록을 비교하고, 두 기록을 연결할지 말지를 필드별로 이유와 함께 알려 주는 Rust 라이브러리입니다.

## 왜 있는가

서로 다른 사람의 두 기록을 연결하면 병력이 섞여 두 사람 모두에게 해가 될 수 있습니다. 그래서 매처는 조용히 결정하지 않습니다. 누락된 필드는 누락된 것으로 보고되고 일치로 계산되지 않으며, 일부 공백은 자동 연결 자체를 막습니다.

## 직접 해 보기

가상의 두 기록입니다. 성과 생년월일은 같지만, 두 번째에는 이름이 없습니다.

```sh
git clone https://github.com/electronic-patient-record/electronic-patient-record.git
cd electronic-patient-record/electronic-patient-record-matcher-with-rust
echo '{"names":[{"family":"Rivera","given":["Alex"]}],"birth_date":"1980-04-12","sex":"female"}' > a.json
echo '{"names":[{"family":"Rivera","given":[]}],"birth_date":"1980-04-12"}' > b.json
cargo run -- a.json b.json
```

출력의 일부:

```json
{
  "score": 1.0,
  "decision": "review",
  "fields": [
    { "field": "family_name", "similarity": 1.0, "weight": 0.25, "note": "similarity 1.00" },
    { "field": "given_name", "similarity": null, "weight": 0.2, "note": "no given name on one or both records" },
    { "field": "birth_date", "similarity": 1.0, "weight": 0.3, "note": "similarity 1.00" }
  ],
  "conflicts": [ "given name not available to confirm the link" ]
}
```

## 놀라웠던 점

두 기록이 공유하는 모든 필드가 일치하므로 점수는 1.0인데도, 매처는 연결을 거부합니다. 이름이 없으면 연결을 확인할 수 없으므로 사람에게 넘깁니다. 높은 점수만으로는 충분하지 않습니다.

임계값은 검증되지 않았으며, 이 소프트웨어는 임상 용도로 사용할 수 없습니다.

## 여러분의 것도 공유하세요

만든 것을 여기에 새 토론으로 게시하고 다음을 포함하세요.

- 그것이 무엇인지, 한 문장으로.
- 왜 만들었는지.
- 볼 만한 것: 스니펫, 스크린샷 또는 링크.
- 다른 사람이 시도해 보는 방법.
- 원하는 피드백의 종류.

가상의 기록만 사용하고, 실제 환자 데이터는 절대 사용하지 마세요. 그리고 다른 사람의 작업을 바탕으로 했다면 그 사람의 공을 밝혀 주세요.
